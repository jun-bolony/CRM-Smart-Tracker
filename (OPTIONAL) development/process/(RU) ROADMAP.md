## Суть проекта

Это веб-приложение, которое помогает соискателям (или любым пользователям, управляющим множеством задач) систематизировать процесс поиска работы. Вместо того чтобы держать в голове или в хаотичной таблице все этапы взаимодействия с потенциальными работодателями, пользователь получает единую панель, где можно:
- Добавлять вакансии с детальной информацией (компания, контакт, ссылка на вакансию, зарплатная вилка).
- Отслеживать статус каждой заявки (например, «Отклик отправлен», «Собеседование назначено», «Тестовое задание», «Оффер», «Отказ»).
- Делать заметки по каждому этапу (впечатления, вопросы, договорённости).
- Устанавливать даты ключевых событий (дедлайны, даты собеседований).
- Фильтровать и сортировать заявки по статусу, дате, компании.
- Главная «фишка» – видеть наглядную аналитику: сколько заявок на каждом этапе, как меняется прогресс во времени, какие каналы поиска наиболее эффективны (если добавить поле «источник»).

Таким образом, это мини-CRM (Customer Relationship Management), адаптированный под управление отношениями с работодателями.


## Пользовательские роли и сценарии

В базовой версии приложение однопользовательское – каждый пользователь управляет только своими данными (если добавить регистрацию/логин, то данные изолированы). Основной сценарий:
1. Пользователь регистрируется/логинится (опционально – можно начать без регистрации, храня данные в локальном хранилище, но для демонстрации fullstack навыков лучше сделать с БД и JWT).
2. Переходит на главную страницу – список всех заявок (таблица или канбан-доска).
3. Добавляет новую заявку через форму.
4. По мере продвижения изменяет статус, добавляет комментарии, устанавливает напоминания.
5. На вкладке «Аналитика» видит графики и статистику.


## Функциональные возможности (по пунктам)

1. **Управление заявками (CRUD)**
- **Создание:** форма с полями:
  - Название компании (обязательно)
  - Должность (обязательно)
  - Ссылка на вакансию (опционально)

  - Контактное лицо (имя, email/телефон)

  - Зарплатная вилка (от/до)

  - Источник (LinkedIn, DOU, рекомендация, сайт компании и т.д.)

  - Статус (выпадающий список)

  - Дата отправки отклика (по умолчанию сегодня)

  - Заметки (текстовое поле)

  - Дата следующего события (дедлайн, собеседование)

- **Чтение:** отображение списка заявок в виде таблицы или карточек с сортировкой и фильтрацией.

- **Обновление:** редактирование любого поля, быстрая смена статуса (например, через выпадающий список прямо в таблице).

- **Удаление:** с подтверждением.

2. **Фильтрация и поиск**
   - Фильтр по статусу (например, показать только «Активные»).

   - Фильтр по источнику.

   - Поиск по названию компании или должности (полнотекстовый).
   
   - Сортировка по дате создания, дате следующего события, зарплате.

3. **Детальная карточка заявки**
При клике на строку открывается отдельная страница/модальное окно с полной информацией и лентой заметок (история изменений статуса и комментариев). Это позволяет вести хронологию общения.

4. **Аналитический дашборд**
На отдельной странице выводятся:

- Круговая диаграмма – распределение заявок по статусам (активные, офферы, отказы, отклики без ответа).

- Гистограмма – количество заявок по дням/неделям (показывает динамику активности).

- Воронка – сколько заявок перешло на следующий этап (от отклика до собеседования, от собеседования до оффера) – классическая воронка продаж.

- Статистика – общее количество заявок, средний срок ответа, успешность (процент офферов).

- Топ источников – столбчатая диаграмма, показывающая, с каких платформ приходит больше всего откликов (полезно для оптимизации стратегии поиска).

5. **Дополнительные «плюшки» (можно реализовать по желанию)**
- Автоматическое создание заметок при изменении статуса (в ленту добавляется запись «Статус изменён на "Собеседование" 2026-07-19»).

- Экспорт данных в JSON/CSV (бэкап или анализ в Excel).

- Email-напоминания о предстоящих собеседованиях (для этого потребуется интеграция с nodemailer или внешним сервисом).

- Темная/светлая тема.


## Как это может эволюционировать

После базовой реализации можно усложнить проект:
- Добавить канбан-доску (перетаскивание карточек между колонками статусов) – это будет выглядеть очень эффектно.
- Интегрировать API внешних сервисов (например, автоматически подтягивать данные о компании по ссылке на вакансию).
- Реализовать многопользовательский режим с возможностью приглашать коллег (командный поиск работы).
- Добавить push-уведомления через Service Workers.

## Примечания по приоритетам
1. **Основной функционал (CRUD + базовый UI)** должен быть реализован в первую очередь – это минимально жизнеспособный продукт (MVP).
2. **Аналитика и фильтры** – второй приоритет, так как они являются ключевыми «фишками» проекта.
3. **Аутентификация** – добавляется после MVP, чтобы не усложнять начальную разработку.
4. **Дополнительные фичи** – опциональны и реализуются по мере желания и времени.
