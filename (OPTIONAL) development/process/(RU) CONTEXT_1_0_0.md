### 2.2. Описание модулей

- **Backend**  
  - `server.js` – инициализирует Express-приложение, подключается к MongoDB (через Mongoose), настраивает CORS, JSON-парсинг и запускает сервер.  
    - Подключены публичные роуты `/api/auth`, защищённые роуты `/api/applications` и `/api/stats` с middleware `auth.js`.
  - **Модель Application** – описана в `models/Application.js` согласно контракту, включает все поля, валидацию, индексы. Поле `userId` обязательно используется для изоляции данных пользователей.
  - **Модель User** – описана в `models/User.js` с полями `email`, `passwordHash`, `createdAt`. Использует `bcrypt` для хеширования паролей.
  - **Контроллеры** – в `controllers/applications.js` реализованы все CRUD-операции с обработкой ошибок и валидацией, а также поддержка фильтрации по статусу (множественный выбор через запятую), источнику, поиска по названию компании и должности, сортировки по полям (`appliedDate`, `nextEventDate`, `salaryMax`) и пагинации. Все запросы фильтруются по `userId`, полученному из JWT.
    - Особенность: при обновлении статуса запись в `statusHistory` добавляется атомарно через оператор `$push`, а всё обновление выполняется через `findByIdAndUpdate` с опцией `{ new: true }`, что гарантирует корректное сохранение истории и возврат актуального документа.
    - `stats.js` – агрегирует статистику для дашборда, также фильтруя по `userId`.
    - `auth.js` – обрабатывает регистрацию и логин, возвращает JWT-токен.
  - **Роуты** – в `routes/applications.js` определены эндпоинты с проверкой валидности ObjectId.
    - `stats.js` – определяет маршрут `GET /api/stats`, который вызывает контроллер `getStats`.
    - `auth.js` – определяет `POST /api/auth/register` и `POST /api/auth/login`.
  - **Middleware** – `auth.js` проверяет наличие и валидность JWT в заголовке Authorization, извлекает `userId`.
    - `errorHandler.js` – централизованный обработчик ошибок.

- **Frontend**  
  – сборка на Vite с поддержкой React и TypeScript.
  - Используются Material-UI для компонентов интерфейса, Recharts для графиков, Axios для HTTP-запросов, React Router для навигации.
  - Основной функционал реализован в компонентах: список заявок с панелью фильтрации (текстовый поиск, множественный выбор статусов, фильтр по источнику, сортировка, кнопка сброса), форма добавления/редактирования, модальные окна для подтверждения удаления и отображения ошибок.
  - Фильтры на фронтенде используют debounce (500 мс) для автоматического обновления списка при вводе.
  - Добавлена страница `ApplicationDetailPage`, на которой отображается полная информация о заявке, доступна смена статуса (с автоматическим добавлением записи в историю), добавление новых заметок и просмотр всей хронологии изменений статусов. История сортируется от новых к старым.
  - Добавлена страница `Dashboard` (путь `/dashboard`), на которой отображаются:
    - Карточки с общей статистикой (всего заявок, офферов, процент успешности).
    - Круговая диаграмма распределения заявок по статусам.
    - Столбчатая диаграмма топ-5 источников.
    - Гистограмма динамики заявок за последние 30 дней.
    - Воронка переходов между статусами.
  - Все графики построены с использованием Recharts и адаптивны.
  - В `ApplicationListPage` добавлена кнопка для перехода на дашборд и кнопка выхода.
  - Добавлен экспорт данных – кнопка "Export" в AppBar, при клике открывается меню с выбором формата (CSV или JSON). Данные скачиваются в виде файла с текущей датой.
  - Реализована тёмная/светлая тема – с помощью контекста `ThemeContext` и компонента `ThemeToggle` (иконка луны/солнца в AppBar). Выбор темы сохраняется в `localStorage`.
  - Реализована аутентификация:
    - Контекст `AuthContext` управляет состоянием токена, пользователя, предоставляет методы `login`, `register`, `logout`.
    - `ProtectedRoute` защищает маршруты, перенаправляя неавторизованных пользователей на `/login`.
    - Страницы входа и регистрации используют MUI-формы.
    - `api.ts` дополнен функциями `login` и `register`, а также перехватчиками для автоматической подстановки JWT в заголовки и обработки 401 (редирект на логин).
  - Оптимизация производительности (добавлено в v.0.9.0):  
    - Компоненты `ApplicationListPage`, `ApplicationTable`, `ApplicationForm` обёрнуты в `React.memo` для предотвращения лишних перерисовок.  
    - В `ApplicationListPage` использованы `useMemo` для параметров запроса и `useCallback` для функций, передаваемых в дочерние компоненты.  
    - Внедрена **ленивая загрузка** страниц через `React.lazy` и `Suspense` в `App.tsx`, что уменьшает начальный размер бандла.  
  - Улучшение обработки ошибок (добавлено в v.0.9.0):  
    - Добавлен глобальный `ErrorBoundary` (классовый компонент), который перехватывает ошибки рендеринга и показывает дружественное сообщение с кнопкой "Try again".  
  - Адаптивный дизайн (добавлено в v.0.9.0):  
    - Панель фильтров в `ApplicationListPage` адаптирована: на экранах `xs` все поля растягиваются на 100% ширины и выстраиваются в колонку.  
    - Кнопки в `AppBar` скрывают текст на маленьких экранах, остаются только иконки.  
    - Таблица заявок в `ApplicationTable` получила горизонтальную прокрутку для корректного отображения на узких экранах.  
    - Форма создания/редактирования в `ApplicationForm` адаптирована: поля перестраиваются в один столбец на мобильных.  
  - Соблюдение правил оформления кода:  
    - Все импорты типов используют `import type` для совместимости с `verbatimModuleSyntax`.  
    - Системные пропсы MUI перенесены в объект `sx`.  
    - Для `TextField` с типом `date` используется `slotProps={{ inputLabel: { shrink: true } }}`.  
    - Все страницы экспортируются по умолчанию для корректной работы `React.lazy`.

## 4. Глобальные правила разработки

### 4.1. Стиль кода

- **Backend** (Node.js):
  - Использовать **CommonJS** (`require` / `module.exports`), так как в `package.json` не указан `"type": "module"`.
  - Все переменные окружения получать через `process.env` (с помощью `dotenv`).
  - Обработка ошибок: использовать `try/catch` в асинхронных контроллерах и передавать ошибки через `next(err)` в Express.
  - Именование файлов: `kebab-case` для файлов (`user-model.js`, `applications-routes.js`).

- **Frontend** (React + TypeScript):
  - Использовать **функциональные компоненты** с хуками.
  - Стилизовать компоненты с помощью **Material-UI** – предпочтительно использовать `sx`-пропсы.
  - Типизация: строгая типизация всех пропсов, состояния, ответов API.
  - Именование: компоненты – `PascalCase`, файлы – `PascalCase` для компонентов (`ApplicationList.tsx`), утилиты – `camelCase`.
  - При использовании `verbatimModuleSyntax` все импорты типов должны быть с `import type`.
  - Для оптимизации производительности использовать `React.memo`, `useMemo`, `useCallback` в тяжёлых компонентах.  
  - Для ленивой загрузки страниц использовать `React.lazy` и `Suspense`.  
  - Для глобального перехвата ошибок рендеринга использовать `ErrorBoundary`.

### 4.2. Организация API

- Базовый URL для API: `VITE_API_URL` (frontend) / `https://your-backend.onrender.com` (продакшн).
- Все эндпоинты для работы с заявками будут иметь префикс `/api/applications`.
- Ответы API должны быть в формате JSON и содержать поля:
  ```typescript
  {
    success: boolean;
    data?: any;          // полезная нагрузка
    message?: string;    // сообщение об ошибке или успехе
  }```
- Коды HTTP: 200 (OK), 201 (Created), 400 (Bad Request), 404 (Not Found), 500 (Internal Server Error).

### 4.3. Работа с базой данных

- Использовать Mongoose для моделирования данных.
- Схемы описывать в папке backend/models/.
- Подключение к MongoDB выполняется один раз при старте сервера, затем используется единый экземпляр соединения.
- При ошибке подключения сервер должен завершиться с кодом 1 (процесс падает, чтобы Render перезапустил его).

### 4.4. Переменные окружения
- **Backend** (.env):
  - PORT – порт, на котором слушает сервер (по умолчанию 3000).
  - MONGODB_URI – строка подключения к MongoDB Atlas (обязательна).
  - JWT_SECRET – секрет для подписи токенов (обязателен, добавлен в Этапе 6).

- **Frontend** (на Vercel):
  - VITE_API_URL – полный URL бэкенда (например, https://crm-backend.onrender.com).

## 7. Инструкция для ИИ-ассистента

**При работе над проектом, пожалуйста, учитывай:**
- Все новые функции должны соответствовать описанным интерфейсам.
- При генерации кода на frontend используй Material-UI для компонентов, а для графиков – Recharts.
- На backend всегда обрабатывай ошибки и возвращай ответ в формате ApiResponse.
- Соблюдай принципы чистого кода: разделяй логику, используй middleware, не дублируй код.
- При добавлении новых страниц или компонентов обновляй маршрутизацию и типы.
- В коде файлов не должно быть кириллицы - весь код, включая даже комментарии в нём, должны быть на английском.
- Обрати внимание на актуальную версию типа ApplicationQueryParams – поле status теперь строка, а не массив. Это критично для правильной передачи параметров в запросе.
- На фронтенде при использовании MUI компонентов всегда применяй sx-пропсы для стилизации, а не устаревшие makeStyles. Для импорта типов из MUI используй import type { ... }. Для SelectChangeEvent обязательно указывай import type { SelectChangeEvent } из @mui/material, чтобы избежать ошибок сборки с verbatimModuleSyntax.
- Особенности реализации статусной истории: при обновлении статуса на бэкенде запись в statusHistory добавляется атомарно через оператор $push, а всё обновление выполняется через findByIdAndUpdate с опцией { new: true }. Это гарантирует сохранность истории и возврат актуального документа. При любых изменениях, затрагивающих статус, необходимо придерживаться этого подхода, чтобы история не терялась и не дублировалась.
- При работе с аутентификацией:
  - Все защищённые эндпоинты ожидают заголовок Authorization: Bearer <token>.
  - На бэкенде используй middleware auth.js для извлечения req.userId.
  - На фронтенде используй контекст AuthContext и компонент ProtectedRoute.
  - В api.ts уже настроены перехватчики для автоматической подстановки токена и обработки 401.
- Новые рекомендации по оптимизации и качеству (v.0.9.0):
  - Для компонентов, которые могут часто перерисовываться (таблицы, формы, списки), используй React.memo.
  - В компонентах с тяжёлыми вычислениями или зависимостями от пропсов применяй useMemo и useCallback.
  - Для страниц, которые не нужны при начальной загрузке, применяй ленивую загрузку через React.lazy и Suspense.
  - Всегда оборачивай корневой компонент в ErrorBoundary для перехвата ошибок рендеринга.
  - При адаптивной вёрстке используй breakpoints MUI (xs, sm, md и т.д.) внутри sx или через useMediaQuery.
  - Убедись, что все страницы экспортируются по умолчанию (export default), чтобы React.lazy работал корректно.
